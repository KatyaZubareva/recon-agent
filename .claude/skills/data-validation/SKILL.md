# Валидация данных 1С

## Когда применять
- Перед импортом или сверкой, если надо убедиться, что 1С отдаёт данные по CONTRACT.md.
- Когда импорт завершился статусом `rejected` или `error` и нужно объяснить причину.
- После добавления нового правила (например, `required_account_id`) — показать, что оно работает.

## Входные параметры
- Нет обязательных. Источник и учётка reader заданы в `.env.agent`.
- Для точечной проверки: `collection` (accounts | charges | payments), `period` (YYYY-MM).

## Команды
Только чтение, ничего не импортируется.
1. `mcp__recon__list_rules` — какие правила валидации зарегистрированы (stage = validate).
2. `mcp__recon__validate_source` — прогнать все правила по данным 1С.
3. При проблемах — `mcp__recon__onec_read` (collection, period), чтобы показать проблемные записи 1С.
4. Если вопрос про прошлый импорт — `mcp__recon__pg_read` с `query=import_runs` (status, problems, error).

То же без агента: `uv run --env-file .env.agent python -c "from recon import agent_tools as t; print(t.validate_source(t.default_source()))"`.

## Проверяемый результат
- `status`: `ok` (нарушений нет) | `problems` (список) | `error` (1С недоступна — это НЕ «данные в порядке»).
- `counts` — сколько записей прочитано из 1С (эталон fixtures: accounts 2, charges 4, payments 1).
- `rules` — какие правила реально применены.
- Для каждой проблемы: `rule`, `entity`, `record_id`, `message`. В ответе пользователю
  обязательно назвать ID записей и правило; не придумывать проблем, которых нет в выводе.
- Числа и суммы брать из вывода инструментов, не пересчитывать «в уме».
