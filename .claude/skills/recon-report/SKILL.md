# Сверка начислений и отчёт

## Когда применять
- Пользователь просит сверить начисления за месяц или объяснить расхождения.
- Нужно подтвердить, что после импорта/восстановления данные совпадают.

## Входные параметры
- `period` — месяц в формате `YYYY-MM` (например, `2026-08`). Если пользователь назвал месяц
  словами — перевести в этот формат; если месяц не назван — спросить.

## Команды
Только чтение; импорт агент не запускает (у него нет прав на запись).
1. `mcp__recon__run_reconciliation` (period) — та же сверка, что на веб-странице. Возвращает
   `run_id`, `status`, итоги `source`/`target`, `discrepancies`, путь `report_file`.
2. Для объяснения каждого расхождения — подтвердить по обоим источникам:
   - 1С: `mcp__recon__onec_read` (collection=charges, period);
   - PostgreSQL: `mcp__recon__pg_read` (query=charge_by_id, record_id) или
     (query=charges_by_period / totals_by_period, period).
3. Если нужен прошлый отчёт из UI — `pg_read` с `recon_runs`, затем `recon_discrepancies` (run_id).

То же без агента: `uv run --env-file .env python -m recon reconcile --period 2026-08`.

## Проверяемый результат
- Отчёт содержит: период, `run_id`, статус, количество и сумму (в копейках) по 1С и по
  PostgreSQL, файл отчёта `artifacts/reports/recon-<period>-<run_id>.json`.
- `status`:
  - `ok` — расхождений нет; всё равно назвать итоги обеих сторон, а не просто «успех»;
  - `discrepancies` — для каждого: тип, ID записи, значение в 1С и в PostgreSQL;
  - `error` — сверка НЕ выполнена (1С или PG недоступны). Никогда не говорить «всё совпадает».
- Типы: `missing_in_target` (нет в PG), `missing_in_source` (нет в 1С), `amount_mismatch`,
  `account_mismatch`, `totals_mismatch` (итоги месяца, без ID).
- Арифметику (суммы, разницы) берём из отчёта — её считает код, не модель.
- В конце: краткий вывод и что сделать (например, повторный импорт восстановит записи из 1С —
  его запускает пользователь кнопкой «Импорт» или `scripts/pg_discrepancies.py restore`).
