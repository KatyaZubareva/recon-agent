# Контракт источника, версия 1

В комплекте используется HTTP JSON: GET `/accounts`, `/charges`, `/payments`.
Ответ `{ "value": [...] }`; все строки находятся в одном ответе без пагинации.
Записи и связи фиксированы в `fixtures/data.json`. Изменять источник для внесения
расхождений нельзя. Отсутствие ответа/HTTP error не равно пустому списку.

| Сущность | Поля |
|---|---|
| accounts | id: string, account_number: string |
| charges | id: string, account_id: string, period: YYYY-MM, amount_kopecks: integer |
| payments | id: string, account_id: string, date: YYYY-MM-DD, amount_kopecks: integer |

Суммы в копейках, RUB; арифметика целочисленная или decimal, не float.
Август 2026: 3 начисления, всего 1 140 000 копеек. По счёту 10001 — 150 000,
по 20002 — 990 000. Сентябрь — отдельная запись для проверки границы периода.
Платежи импортируются с сохранением ID и связей. **Обязательная сверка — начисления**;
сверка платежей не требуется. Счета импортируются как справочник.

Для реальной 1С кандидат выбирает имена объектов и описывает mapping на эти поля.
Допустимы нативные UUID 1С с устойчивым сопоставлением на ID из fixtures/data.json. HTTP mock не реализует OData `$filter`, `$select` или `$metadata`.
При использовании OData кандидат учитывает контракт конкретной публикации;
кандидат описывает пагинацию, единицы суммы и формат месяца.
