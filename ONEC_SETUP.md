# Кандидату: самостоятельно развернуть 1С

Это обязательная часть full-stack задания, версия 2.1. Готовый стенд 1С не выдаётся.
В стартовом Compose только HTTP mock и PostgreSQL. Mock не является реализацией 1С.

## Результат подготовки

1. Установите платформу 1С из официального дистрибутива и активируйте доступную вам
   законную лицензию для разработки. Зафиксируйте версию платформы и способ установки.
2. Создайте минимальную конфигурацию с тремя сущностями из `CONTRACT.md`:
   лицевой счёт, начисление, платёж. Бухгалтерия, проводки, типовые конфигурации и
   полноценные формы 1С не нужны. Допустимо использовать подходящую легально доступную демобазу.
3. Загрузите `fixtures/data.json`. Сохраните стабильные ID либо документируйте
   сопоставление ID фикстур с нативными UUID 1С. Подтвердите суммы и связи.
4. Опубликуйте HTTP JSON по контракту либо стандартный OData и опишите mapping полей.
   Создайте отдельного пользователя только с чтением. Заполните ONEC_* в `.env`.
5. Добавьте исходники конфигурации или разрешённую к передаче выгрузку, скрипт загрузки
   данных и реальную команду восстановления демобазы; проверьте повторный запуск.
6. Выполните `uv run --env-file .env python scripts/preflight.py --real`, затем подтвердите
   эталонные значения и отказ записи с read-only доступом. Preflight проверяет только чтение.

Docker для самой 1С предпочтителен, но допустим локальный запуск или VM:
задокументируйте установку и подключение приложения к источнику.
Приложение и отдельная отчётная PostgreSQL по-прежнему запускаются через Compose.
Не коммитьте установщики, файлы лицензий, PIN-коды и секреты.

## Доступ и лимит времени

Получите доступ к официальному дистрибутиву и лицензии до начала отсчёта.
Начать можно с [портала разработчиков 1С](https://developer.1c.ru/).
[Условия комьюнити-лицензии](https://v8.1c.ru/podderzhka-i-obuchenie/uchebnye-versii/)
предусматривают использование для разработки и регистрацию с подтверждением телефона.
Наличие лицензии само по себе не гарантирует доступ к нужному дистрибутиву.
Если получение дистрибутива или активация заблокированы, сообщите организатору:
покупать лицензию или обходить активацию не требуется. Ожидание внешнего доступа
не входит в активное время; организатор помогает получить законный доступ.

После проверки доступов: до **4 часов на подготовку 1С** и до **12 часов на приложение**,
в пределах 2–3 календарных дней. В отчёте учитывайте эти этапы отдельно.
При достижении лимита сдайте сделанное и укажите точную блокировку; подменять
интеграционный результат успешным mock-прогоном нельзя. Отсутствие рабочего стенда
из-за незавершённой настройки оценивается как незавершённая часть задания,
а недоступность дистрибутива/активации — как внешняя блокировка.
Доступы к coding/CLI agent и реальной модели с квотой выдаёт организатор.
